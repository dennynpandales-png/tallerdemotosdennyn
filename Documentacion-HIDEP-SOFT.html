02 · Ejemplo de módulo
Órdenes de servicio

Una orden organiza el trabajo de la moto

La pantalla permite buscar órdenes, elegir una moto y un mecánico, definir el tipo de mantenimiento y dejar el motivo de ingreso. Las acciones posteriores registran el avance, la mano de obra y los repuestos.

Vista de ejemplo: filas y nombres son ficticios. La pantalla real puede cambiar según permisos, datos registrados y tamaño de ventana.

Etapas de una orden

1 · Registrar

Asociar moto, mecánico, tipo y motivo.

2 · Atender

Describir trabajo y pedir piezas. La aprobación descuenta inventario.

3 · Cobrar

Revisar el total y marcar como facturada.

Regla de inventario: la solicitud del mecánico no descuenta existencias hasta que recepción la aprueba.

04 · Proceso del negocio
UML · Diagrama de actividad

Flujo de una orden desde recepción hasta caja

El flujo incorpora el desvío opcional de repuestos: si se necesitan, el mecánico envía una solicitud y recepción decide si puede atenderse según el stock.

El sistema permite guardar una solicitud pendiente; la aprobación verifica unidades disponibles antes de descontar inventario y agregar el repuesto a la cuenta.

Nota de lectura: los nombres al inicio de cada actividad identifican quién la realiza. El rombo es una decisión; el círculo inicial y el círculo doble final indican comienzo y cierre del proceso.

UML · Componentes y despliegue

Del escritorio a la base de datos

La aplicación agrupa la interfaz en Electron, sirve archivos estáticos con Express y persiste la información en SQLite. El servidor escucha en la interfaz de red local del propio equipo.

Estados y cálculos visibles

Orden

En proceso trabajo abierto; Facturada cobrada. El esquema también incluye Finalizada para registros heredados.

Cita / repuesto

Las citas empiezan como Pendiente. Una solicitud de pieza comienza Solicitado y al aprobarse cambia a Aprobado.

  • Al aprobar una solicitud se valida el stock, se descuentan unidades y se guarda el precio de venta vigente como precio unitario.
  • El reporte suma mano de obra y venta de repuestos facturados; el código estima la ganancia de repuestos como el 30% de esa venta.
  • Las tarifas configurables consideran categorías de cilindraje 100, 200, 400 y superior.
Privacidad: esta guía describe el esquema, no reproduce nombres, cédulas, placas, transacciones ni otros datos de los archivos .db.
Hay varias bases en la carpeta. El backend actual usa database.db en modo fuente. database.sqlite, taller.db, taller_motos.db y los archivos taller_backup_*.db tienen esquemas distintos o corresponden a otras copias. No borrarlos ni mezclarlos sin respaldo e identificación.

10 · Operación y continuidad
Respaldo y restauración

Proteger los datos del taller

Pasos habituales

  1. En Configuración → Copias de Seguridad, elegir una carpeta accesible y protegida.
  2. Crear respaldo. El nombre sigue el formato taller_backup_<fecha>.db.
  3. Guardar varias copias, separar al menos una del computador y comprobar periódicamente la restauración.
  4. Al restaurar, seleccionar un .db válido. El servidor comprueba SQLite y las tablas, respalda la base actual y pide reiniciar.

Modo desarrollo

database.db en la carpeta del proyecto.

Aplicación instalada

Directorio userData de Electron bajo AppData. La app copia allí la plantilla inicial si es necesario.

Restablecer sistema elimina registros operativos; no es lo mismo que cerrar sesión. Respaldar y confirmar antes de utilizar esa opción.

El diálogo de cierre de Electron también ofrece crear una copia antes de salir. Si el destino no está configurado, primero debe elegirse desde la sección de respaldos.

12 · Alcance y buenas prácticas
Notas para el equipo

Qué está implementado y qué cuidar

Contraseñas

El servidor usa scrypt con sal para proteger contraseñas y respuestas de recuperación; también puede migrar contraseñas antiguas al iniciar.

Cuenta inicial

Si la base no tiene usuario admin, el código actual crea admin / 1234. Configure recuperación y reemplace esa contraseña al instalar.

Roles / permisos

El tablero puede mostrar módulos según los permisos elegidos. El servidor actual escucha localmente; no se debe exponer a una red sin reforzar autorización por endpoint.

Pruebas

npm run test:smoke comprueba flujos principales, incluida la copia y restauración en una carpeta temporal.

Recomendaciones para usarlo con tranquilidad

  • Restringir el acceso al computador y a los archivos .db: guardan información personal y comercial.
  • Hacer respaldo antes de actualizar, migrar o sustituir archivos de base de datos.
  • Probar una restauración de forma controlada y mantener más de una copia independiente.
  • No presentar las ilustraciones de las páginas 03–04 como capturas literales: son modelos visuales con información de ejemplo.
Nota técnica importante: el login entrega permisos al panel, pero en el backend revisado no se observa una capa general de sesión/autorización para cada ruta. El diseño actual es de uso local en un solo equipo, no un servicio multiusuario para Internet.
